Why this is different
No req, no res: declare parameters, return data
The biggest mental shift in this whole course. An Express handler receives two grab-bag objects and digs what it needs out of them. A FastAPI handler lists exactly the inputs it wants as typed function parameters and just returns a value.
Express
app.get("/employees/:id", (req, res) => {
  const id = Number(req.params.id);   // dig it out
  const limit = req.query.limit;      // string | undefined
  res.status(200).json({ id, limit });
});
FastAPI
@app.get("/employees/{id}")
async def get_one(id: int, limit: int = 20):
    return {"id": id, "limit": limit}
    # path param, query param, status code
    # and response: all inferred
FastAPI inspects the signature: a name that appears in the path is a path parameter, other simple types are query parameters, a Pydantic model is the JSON body. Returning a dict serialises it as JSON with a 200. No object to mutate, no res.json() call you can forget or call twice. We will use every one of these rules in the next chapters.

Why this is different
The type hint is the validator
In Express, validation is something you bolt on: parse manually, or write a Zod schema and call .parse() inside (or middleware before) each handler. In FastAPI the annotation you already wrote for your editor is read at runtime and enforces itself.
Express
const Params = z.object({ id: z.coerce.number().int() });

app.get("/employees/:id", (req, res) => {
  const p = Params.safeParse(req.params);
  if (!p.success) return res.status(400).json(p.error);
  // ... p.data.id is now a number
});
FastAPI
@app.get("/employees/{employee_id}")
async def get_employee(employee_id: int):
    # employee_id is already an int here,
    # or this function never ran.
    ...
Types are normally erased in Python, exactly like TypeScript (see the cheatsheet row). FastAPI and Pydantic are the deliberate exception: they read your hints at runtime to coerce "3" into 3, reject "abc", enforce enum membership for role, and write the same rules into the OpenAPI schema. One declaration, three jobs.

Chapter 1 takeaways
  • Path params come from the route string, query params from everything else.
  • A default value makes a parameter optional; a type makes it validated.
  • HTTPException is how you return an error from anywhere in a handler.
  • 422 means "your request was malformed"; 404 means "well-formed, but not there".

POST with a response model


app/main.py  (added endpoint)
@app.post(
    "/employees",
    response_model=EmployeeRead,
    status_code=201,
    summary="Create an employee",
)
async def create_employee(payload: EmployeeCreate) -> dict:
    """Create an employee. Returns the new record without salary."""
    if any(e["email"] == payload.email for e in EMPLOYEES):
        raise HTTPException(status_code=409, detail="Email already in use")
    new = {
        "id": max(e["id"] for e in EMPLOYEES) + 1,
        **payload.model_dump(),
        "employment_status": "active",
        "password_hash": "!unset",   # Part 2 (ch 6) sets this for real
    }
    EMPLOYEES.append(new)
    return new


1
payload: EmployeeCreate is a Pydantic model, so FastAPI reads the JSON body into it, like req.body but parsed and checked first.
2
model_dump() turns the validated model into a plain dict. {**a, "k": v} is object spread.
3
status_code=201 sets the success code; Express would be res.status(201).
4
response_model=EmployeeRead is the output filter. We return the full dict including salary and password_hash; FastAPI validates it against EmployeeRead and keeps only its fields. The secrets cannot leak even if a later edit returns the whole record.
5
The "password_hash" key exists from now on but is never returned. Part 2, chapter 6, starts setting it properly.

from collections.abc import AsyncIterator

from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
from sqlalchemy.orm import DeclarativeBase

engine = create_async_engine("sqlite+aiosqlite:///./app.db")

# expire_on_commit=False: objects stay readable after commit(),
# which we need because we return them to FastAPI after committing.
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)


class Base(DeclarativeBase):
    """Parent class of every ORM model."""


async def get_db() -> AsyncIterator[AsyncSession]:
    """Yield one session per request, always closed afterwards."""
    async with SessionLocal() as session:
        yield session


Why this is different
Depends and get_db: typed, per-request injection
In Express the usual way to hand a handler its database is middleware that bolts a property onto req, and TypeScript then needs a declaration merge to know it exists. FastAPI inverts this: the handler asks for the thing by parameter, and a function you point at produces it.
Express
app.use((req, res, next) => {
  req.db = pool.acquire();
  res.on("finish", () => req.db.release());
  next();
});

app.get("/employees", async (req, res) => {
  const rows = await req.db.query(...);   // typed? only by hand
});
FastAPI
async def get_db():
    async with SessionLocal() as session:
        yield session        # handler runs here
    # session closed after the response

@app.get("/employees")
async def list_employees(
    db: AsyncSession = Depends(get_db),
):
    ...
Everything before yield is setup, everything after is teardown, run even when the handler raises. The result is injected only into routes that ask for it, it is fully typed (your editor knows db is an AsyncSession), it is created fresh per request, and it appears in OpenAPI when it has parameters of its own. The same mechanism will carry "who is the current user" in Part 2. In tests you can swap any dependency for a fake with one line.

# new: Mapped[int | None] → cheatsheet# new: class inheritance → cheatsheet Mapped[T] is the type, mapped_column() adds database options. Mapped[str | None] becomes a nullable column automatically. The enums moved here from main.py.

from datetime import date
from enum import Enum

from sqlalchemy import Enum as SAEnum
from sqlalchemy import ForeignKey, String
from sqlalchemy.orm import Mapped, mapped_column, relationship

from app.db import Base


class Role(str, Enum):
    EMPLOYEE = "employee"
    MANAGER = "manager"
    HR_ADMIN = "hr_admin"


class EmploymentStatus(str, Enum):
    ACTIVE = "active"
    ON_LEAVE = "on_leave"
    TERMINATED = "terminated"


def _values(e: type[Enum]) -> list[str]:
    return [m.value for m in e]   # store "hr_admin", not "HR_ADMIN"


class Department(Base):
    __tablename__ = "departments"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100), unique=True)
    description: Mapped[str | None] = mapped_column(String(500), default=None)

    employees: Mapped[list["Employee"]] = relationship(back_populates="department")


class Employee(Base):
    __tablename__ = "employees"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100))
    email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
    role: Mapped[Role] = mapped_column(
        SAEnum(Role, native_enum=False, values_callable=_values), default=Role.EMPLOYEE
    )
    job_title: Mapped[str] = mapped_column(String(100))
    hire_date: Mapped[date]
    salary: Mapped[int]
    employment_status: Mapped[EmploymentStatus] = mapped_column(
        SAEnum(EmploymentStatus, native_enum=False, values_callable=_values),
        default=EmploymentStatus.ACTIVE,
    )
    department_id: Mapped[int | None] = mapped_column(ForeignKey("departments.id"))
    manager_id: Mapped[int | None] = mapped_column(ForeignKey("employees.id"))
    password_hash: Mapped[str] = mapped_column(String(255))   # set for real in Part 2

    department: Mapped[Department | None] = relationship(back_populates="employees")
    # Self-referential: the "one" side. remote_side says which end is the parent.
    manager: Mapped["Employee | None"] = relationship(
        remote_side="Employee.id", back_populates="reports"
    )
    reports: Mapped[list["Employee"]] = relationship(back_populates="manager")


1
manager_id is a foreign key to the same table. That one column is the entire org chart.
2
remote_side="Employee.id" disambiguates a self-join: it marks the id end as the parent ("remote") side, so manager means "the employee whose id equals my manager_id".
3
reports is the reverse direction: everyone whose manager_id is my id.
4
These relationships exist for completeness. In async code you must not read them lazily (emp.manager would try to do I/O in a sync context and raise). We always query by id columns instead, which is also what the API exposes.

Why PATCH needs exclude_unset


The key line is payload.model_dump(exclude_unset=True). Every field on EmployeeUpdate defaults to None, so without that flag you cannot tell "the client did not send department_id" from "the client sent department_id: null to remove the department".


PATCH /employees/3  ·  what the handler sees
# body: {"job_title": "Staff Engineer"}
payload.model_dump()                    # {"name": None, "role": None, "job_title": "Staff Engineer", ... all the rest None}
payload.model_dump(exclude_unset=True)  # {"job_title": "Staff Engineer"}

# body: {"manager_id": null}   -> explicitly clear the manager
payload.model_dump(exclude_unset=True)  # {"manager_id": None}   <- applied, as intended


That is the whole difference between the verbs. PUT replaces the resource: every field is required and anything omitted is overwritten. PATCH merges: omitted means untouched, explicit null means clear. exclude_unset is what makes that distinction available. DELETE returns 204 No Content: success with an empty body, so the handler returns None.


Why this is different
Blocking calls inside async def
Express is single-threaded too, and you already know the rule: never call fs.readFileSync inside a request handler, because it freezes every other request. The same trap exists here, and Python makes it easier to fall into because the blocking version of a library often has the same name as the async one.
Express
// freezes every request for 2 seconds
app.get("/slow", (req, res) => {
  const data = fs.readFileSync("big.csv");
  res.send(data);
});
FastAPI
import requests            # blocking HTTP client
import sqlite3             # blocking DB driver

@app.get("/slow")
async def slow():
    r = requests.get("https://api.example.com")  # stalls the loop
    return r.json()
An async def handler runs on the event loop. One blocking call inside it stops every in-flight request until it returns. Use the async twins: httpx.AsyncClient instead of requests, and aiosqlite (what our SQLAlchemy URL sqlite+aiosqlite uses) instead of sqlite3. If you must call blocking code, declare the handler as plain def and FastAPI will run it in a thread pool for you, off the loop. The cheatsheet has the side-by-side row. Never mix: async def plus requests is the bad combination; plain def plus requests is fine.

Lists a frontend can actually use


A React table needs more than "all rows": it needs filtering, a search box, sortable columns, pages, and a total count for the pager. This chapter builds all of that once, as reusable pieces, and adds the two endpoints that walk the org chart.

A response envelope: Page[T]


# new: Generic[T] → cheatsheet Returning a bare array makes it impossible to add a total later without breaking clients. Wrap lists in one generic envelope so the React side always gets {items, total, limit, offset}.

from typing import Literal

from fastapi import Query
from sqlalchemy import Select, func, or_

from app.models import EmploymentStatus
from app.schemas import Page


class EmployeeFilters:
    def __init__(
        self,
        department_id: int | None = None,
        role: Role | None = None,
        employment_status: EmploymentStatus | None = None,
        q: Annotated[str | None, Query(description="Search name or email", max_length=100)] = None,
        sort_by: Literal["name", "hire_date", "salary"] = "name",
        order: Literal["asc", "desc"] = "asc",
        limit: Annotated[int, Query(ge=1, le=100)] = 20,
        offset: Annotated[int, Query(ge=0)] = 0,
    ) -> None:
        self.department_id = department_id
        self.role = role
        self.employment_status = employment_status
        self.q = q
        self.sort_by = sort_by
        self.order = order
        self.limit = limit
        self.offset = offset


Filters = Annotated[EmployeeFilters, Depends()]


def apply_filters(stmt: Select, f: EmployeeFilters) -> Select:
    if f.department_id is not None:
        stmt = stmt.where(Employee.department_id == f.department_id)
    if f.role is not None:
        stmt = stmt.where(Employee.role == f.role)
    if f.employment_status is not None:
        stmt = stmt.where(Employee.employment_status == f.employment_status)
    if f.q:
        like = f"%{f.q}%"
        stmt = stmt.where(or_(Employee.name.ilike(like), Employee.email.ilike(like)))
    return stmt


async def page_of_employees(db: AsyncSession, f: EmployeeFilters, base: Select) -> dict:
    base = apply_filters(base, f)
    total = await db.scalar(select(func.count()).select_from(base.subquery()))
    sort_col = {"name": Employee.name, "hire_date": Employee.hire_date, "salary": Employee.salary}[f.sort_by]
    ordering = sort_col.asc() if f.order == "asc" else sort_col.desc()
    stmt = base.order_by(ordering, Employee.id).offset(f.offset).limit(f.limit)
    items = (await db.scalars(stmt)).all()
    return {"items": items, "total": total or 0, "limit": f.limit, "offset": f.offset}


1
Literal["name", "hire_date", "salary"] is a union of string literals, like TS. A client sending sort_by=password_hash gets a 422 listing the allowed values, so the sort key can never be used to probe a column you did not list. It also becomes an enum in OpenAPI.
2
Query(ge=1, le=100) adds constraints to a query param, the same way Field does for bodies. A client cannot ask for limit=100000.
3
or_(name.ilike(...), email.ilike(...)) is SQL name LIKE ? OR email LIKE ?, case-insensitive. The % wildcards are added around the term.
4
The total comes from a count(*) over the filtered query wrapped as a subquery, before limit and offset are applied. That is what the pager needs.
5
The sort column is looked up in a dict whose keys are the only values Literal lets through, never interpolated from user text.


🔐

Dependencies compose and are cached


A dependency can itself declare dependencies. Filters needs nothing, but a route that takes both db: DbSession and f: Filters already shows the idea: FastAPI builds a graph from the signatures and resolves it per request. If two dependencies in the same request both depend on get_db, it runs once and both receive the same session, because results are cached per request by default (pass use_cache=False to opt out). This is why Part 2 can stack "current user", then "must be manager", then "owns this resource" without opening three database sessions.

  • Literal and Query(ge, le) make sort keys and page sizes safe by construction.
  • A class with a typed __init__ is a reusable bundle of query params.
  • Dependencies form a graph resolved per request, with results cached.

Database setup and WAL mode


Two SQLite pragmas run on every new connection. journal_mode=WAL switches to write-ahead logging: readers no longer block on the writer, so a GUI (the VS Code SQLite Viewer extension, the sqlite3 CLI, or DB Browser for SQLite) can read app.db while uvicorn holds it open. Without it you hit "database is locked" the moment you inspect data mid-request. foreign_keys=ON is needed because SQLite ignores foreign keys by default; without it manager_id: 999 would silently be accepted.


app/core/db.py
from sqlalchemy import event
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine

from app.core.config import get_settings

engine = create_async_engine(get_settings().database_url)

SessionLocal = async_sessionmaker(engine, expire_on_commit=False)


@event.listens_for(engine.sync_engine, "connect")
def _sqlite_pragmas(dbapi_connection, _record) -> None:
    cur = dbapi_connection.cursor()
    cur.execute("PRAGMA journal_mode=WAL")    # readers don't block the writer
    cur.execute("PRAGMA foreign_keys=ON")     # enforce FKs (off by default in SQLite)
    cur.close()

from sqlalchemy import Select, func, or_, select
from sqlalchemy.ext.asyncio import AsyncSession

from app.deps import EmployeeFilters
from app.models.employee import Employee


async def get_employee(db: AsyncSession, employee_id: int) -> Employee | None:
    result = await db.scalars(select(Employee).where(Employee.id == employee_id))
    return result.one_or_none()


def apply_filters(stmt: Select, f: EmployeeFilters) -> Select:
    if f.department_id is not None:
        stmt = stmt.where(Employee.department_id == f.department_id)
    if f.role is not None:
        stmt = stmt.where(Employee.role == f.role)
    if f.employment_status is not None:
        stmt = stmt.where(Employee.employment_status == f.employment_status)
    if f.q:
        like = f"%{f.q}%"
        stmt = stmt.where(or_(Employee.name.ilike(like), Employee.email.ilike(like)))
    return stmt


async def page_of_employees(
    db: AsyncSession, f: EmployeeFilters, base: Select | None = None
) -> dict:
    base = apply_filters(base if base is not None else select(Employee), f)
    total = await db.scalar(select(func.count()).select_from(base.subquery()))
    sort_col = {
        "name": Employee.name,
        "hire_date": Employee.hire_date,
        "salary": Employee.salary,
    }[f.sort_by]
    ordering = sort_col.asc() if f.order == "asc" else sort_col.desc()
    stmt = base.order_by(ordering, Employee.id).offset(f.offset).limit(f.limit)
    items = (await db.scalars(stmt)).all()
    return {"items": items, "total": total or 0, "limit": f.limit, "offset": f.offset}

from fastapi import APIRouter, HTTPException
from sqlalchemy import select, update
from sqlalchemy.ext.asyncio import AsyncSession

from app.deps import DbSession, Filters
from app.models.employee import Employee
from app.schemas.common import Page
from app.schemas.employee import EmployeeCreate, EmployeeRead, EmployeeUpdate
from app.services import employees as svc

router = APIRouter(prefix="/employees", tags=["employees"])


async def _get_or_404(db: AsyncSession, employee_id: int) -> Employee:
    emp = await svc.get_employee(db, employee_id)
    if emp is None:
        raise HTTPException(status_code=404, detail=f"Employee {employee_id} not found")
    return emp


@router.get("", response_model=Page[EmployeeRead], summary="List employees")
async def list_employees(db: DbSession, f: Filters):
    """Search, filter, sort and paginate employees."""
    return await svc.page_of_employees(db, f)


@router.post("", response_model=EmployeeRead, status_code=201, summary="Create an employee")
async def create_employee(payload: EmployeeCreate, db: DbSession):
    """Create an employee. Returns the new record without salary."""
    dup = await db.scalars(select(Employee).where(Employee.email == payload.email))
    if dup.one_or_none() is not None:
        raise HTTPException(status_code=409, detail="Email already in use")
    emp = Employee(**payload.model_dump(), password_hash="!unset")   # Part 2, ch 6
    db.add(emp)
    await db.commit()
    await db.refresh(emp)
    return emp


@router.get("/{employee_id}", response_model=EmployeeRead, summary="Get one employee")
async def get_employee(employee_id: int, db: DbSession):
    """Fetch a single employee by numeric id."""
    return await _get_or_404(db, employee_id)


@router.patch("/{employee_id}", response_model=EmployeeRead, summary="Update an employee")
async def update_employee(employee_id: int, payload: EmployeeUpdate, db: DbSession):
    """Change only the fields that are present in the request body."""
    emp = await _get_or_404(db, employee_id)
    for field, value in payload.model_dump(exclude_unset=True).items():
        setattr(emp, field, value)
    await db.commit()
    await db.refresh(emp)
    return emp


@router.delete("/{employee_id}", status_code=204, summary="Delete an employee")
async def delete_employee(employee_id: int, db: DbSession) -> None:
    """Delete an employee. Anyone they managed is left with no manager."""
    emp = await _get_or_404(db, employee_id)
    await db.execute(
        update(Employee).where(Employee.manager_id == employee_id).values(manager_id=None)
    )
    await db.delete(emp)
    await db.commit()


@router.get(
    "/{employee_id}/reports",
    response_model=Page[EmployeeRead],
    summary="List an employee's direct reports",
)
async def list_reports(employee_id: int, db: DbSession, f: Filters):
    """Employees whose manager is the given employee."""
    await _get_or_404(db, employee_id)
    base = select(Employee).where(Employee.manager_id == employee_id)
    return await svc.page_of_employees(db, f, base)

main.py, CORS and middleware


The browser blocks your React dev server (localhost:5173) from calling the API (localhost:8000) unless the API opts in; that is CORS, same as app.use(cors()) in Express. Allow exactly the origin you serve from. Do not use ["*"] together with allow_credentials=True: the browser spec forbids a wildcard origin on credentialed requests, and Starlette rejects the combination rather than letting you ship something that silently fails. (Part 2 switches to a bearer token in a header, so credentials stay off for now.)

    response = await call_next(request)

Middleware or Depends?


You now have both tools, and they overlap just enough to confuse. The split:


🌐
Reach for middleware when
It is cross-cutting and applies to every request without a return value the handler needs: request logging and timing, CORS, adding a response header, request ids. It sees raw requests and responses, like app.use(), and knows nothing about which route matched.
🧩
Reach for Depends when
You need to inject a typed value (a session, the current user), it should run only on some routes, or it should show up in OpenAPI (a query parameter bundle, an auth scheme). It can read the same typed parameters a handler can, and tests can override it.


Quick test: if the handler needs something from it, or it needs to be visible in /docs, it is a dependency. Otherwise middleware.
